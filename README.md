# AAIF data archive

Archive copy of the TEI and RDF data of the Open Access Database "Adjective-Adverb Interfaces in Romance" (AAIF), an annotated corpus of Romance adjectives in adverbial function and of prepositional adverbials with an adjectival core, in French, Italian varieties, Portuguese, Romanian, Spanish and Latin. The database is published by the Department of Romance Studies and the Centre for Information Modelling (ZIM) of the University of Graz at https://gams.uni-graz.at/aaif (handle `hdl:11471/513.30`). This repository keeps the datastreams byte for byte as GAMS delivered them, with checksums, and the scripts that fetched and analysed them.

## Contents

| Path | Content |
|---|---|
| `data/tei/` | `TEI_SOURCE` of every corpus object, its bibliography object, the ODD object and the TEI template object, plus the TEI description of the annotation model (`o-aaif.ontology.DESCRIPTION.xml`) |
| `data/rdf/` | `RDF` of every corpus and bibliography object, as generated by GAMS at ingest, and the OWL ontology (`o-aaif.ontology.ONTOLOGY.rdf`) |
| `data/schema/` | The RelaxNG schema generated from the ODD |
| `data/objects.json` | Inventory of every GAMS object whose PID contains `aaif`, with title and datastream list |
| `data/manifest.json` | Every archived file with PID, datastream id, source URL, size, SHA-256 and retrieval date |
| `01_fetch.py` | Discovers the objects through the Fedora object search and fetches the datastreams |
| `02_analyze.py` | Checks TEI and RDF and writes `reports/analysis.json` |

File names follow the pattern `<PID>.<datastream id>.<extension>` with `:` in the PID replaced by `-`. Files under `data/` are stored without line-ending conversion, so their checksums match the manifest on every checkout.

## Usage

The scripts need [uv](https://docs.astral.sh/uv/).

```
uv run 01_fetch.py            # fetch missing datastreams, --force fetches everything again
uv run 02_analyze.py          # analyse TEI and RDF, report in reports/analysis.json
```

`01_fetch.py` sends one request at a time with a pause between requests.

## Known properties of the data

These properties were found by `02_analyze.py` on the copy retrieved on 2026-09-24. They are documented here and left unchanged in the data.

- The RDF uses class and property names of the `aaif:` namespace that the published ontology does not declare (for example `Adjective`, `VerbObject`, `mente`, `overt`, `contracted`), while the ontology declares related names (`Adjectival`, `VerbObjectTarget`, `Derived_mente`, `overtSubject`, `contraction`). The search form of the website uses the names of the RDF.
- The RDF of Fr_A_DHAA, Ro_ADP_aaif and Sp_AP_SH3 lacks the link from the corpus object to its CMDI context, because their TEI headers do not carry `ref[@type='corpus']`.
- Lemma IRIs have the form `https://gams.uni-graz.at/o:aaif.lemma#<lemma>` without a language. Lemmas of equal spelling in different languages share one IRI, and lemmas containing spaces give invalid IRIs.
- In Fr_A_Web some bibliography identifiers carry trailing text such as URLs or dates, so that `xml:id` values in the bibliography are not valid names and some `aaif:source` targets do not resolve. Isolated undefined bibliography references occur in Lt_P_aaif and Sp_AP_Cordiam.
- The stated extent in the TEI headers (examples, tokens) does not match the encoded data in most corpora.
- In Pt_APM_DeG and Ro_ADP_aaif a `p` is a paragraph of running text, many of them without an annotated syntagm, while in the other corpora a `p` is one example.
- `body/@xml:lang` uses `sp` for Spanish and `lt` for Latin.
