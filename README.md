# AAIF data archive

Archive copy of the data of the Open Access Database "Adjective-Adverb Interfaces in Romance" (AAIF), an annotated corpus of Romance adjectives in adverbial function, derived adverbs and adverbial prepositional phrases with an adjectival core, in French, Southern Italian varieties, Latin, Brazilian Portuguese, Old Romanian and Spanish. The database was built by the Department of Romance Studies and the Centre for Information Modelling (ZIM) of the University of Graz and is published at https://gams.uni-graz.at/aaif (handle `hdl:11471/513.30`), managed today by the university's Institute for Digital Humanities. This repository keeps its TEI, RDF, ontology, schema and documentation byte for byte as GAMS delivered them on 2026-09-24, with checksums, and documents what the data contains and where TEI, RDF, ontology and search disagree.

## Contents

| Path | Content |
|---|---|
| `data/tei/` | TEI of the nine corpora and their bibliographies, the ODD and the TEI description of the annotation model |
| `data/rdf/` | RDF of every corpus and bibliography, generated by GAMS, and the ontology |
| `data/schema/` | RelaxNG schema generated from the ODD |
| `data/docs/` | Manual of the Word annotation tool and the description of the annotation model, as PDF |
| `data/manifest.json` | Every archived file with PID, datastream, source URL, size, SHA-256 and retrieval date |
| `data/objects.json` | Inventory of every GAMS object of the database |
| `knowledge/` | Documentation of data, annotation model, decisions and checks, starting at [knowledge/INDEX.md](knowledge/INDEX.md) |
| `01_fetch.py`, `02_analyze.py`, `03_verify.py` | Retrieval, analysis and checksum verification |
| `04_export.py`, `docs/` | Counts of the annotation categories per corpus and the profile view served at https://chpollin.github.io/aaif-data/ |

File names follow the pattern `<PID>.<datastream id>.<extension>` with `:` in the PID replaced by `-`.

## Before reusing the data

The TEI is the normative form of the data. The RDF was generated from it and carries defects of the transformation, which are also visible in the search of the website. The most consequential ones, checked against the live triple store:

- The corpora Fr_A_DHAA, Ro_ADP_aaif and Sp_AP_SH3 lack the link from corpus object to corpus context, so the database search of the website finds none of their examples.
- The attribution target "verb and subject" is written to the RDF as "verb", so it cannot be searched and is merged with the target verb.
- The RDF uses other class and property names than the ontology for part of the categories.

[knowledge/data.md](knowledge/data.md#known-properties) lists every known property, [knowledge/annotation-model.md](knowledge/annotation-model.md) explains the categories, decodes the compact annotation codes in `w/@function` and aligns the names of RDF and ontology.

## Profile view

https://chpollin.github.io/aaif-data/ shows for each annotation category how the tagged adverbs of the nine corpora distribute over its values, for all adverbs or only those inside or outside a prepositional phrase. The counts come from the TEI and mark values that a corpus header does not declare.

## Usage

The scripts need [uv](https://docs.astral.sh/uv/).

```
uv run 03_verify.py           # check every file against the manifest, offline
uv run 02_analyze.py          # analyse TEI, RDF and ontology, report in reports/analysis.json
uv run 01_fetch.py            # fetch missing datastreams from GAMS, --force fetches everything again
uv run 04_export.py           # recount the categories for the profile view
```
